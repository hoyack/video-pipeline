**SequencedSceneList.tsx changes:**

1. Import `SortableContext`, `verticalListSortingStrategy`, and `arrayMove` from `@dnd-kit/sortable`.
2. Import `reorderSequences` and `reorderScenesInSequence` from `../api/client.ts`.
3. Wrap the sequence list (the `{sequences.map(...)}` block) in a `<SortableContext items={sequences.map(s => s.id)} strategy={verticalListSortingStrategy}>` to make sequence headers draggable.
4. Refactor `handleDragEnd` to use type discrimination on `active.data.current?.type`:
   - If `type === "sequence"`: Find old/new index in `sequences` array, call `arrayMove`, optimistically update `setSequences`, then call `reorderSequences(productionId, { sequence_ids: reordered.map(s => s.id) })`. On failure, revert to `previousSequences`.
   - If `type === "scene-within-sequence"`: The active item is a scene being reordered within its sequence. Extract `sequenceId` from `active.data.current.sequenceId`. Find old/new index in localScenes filtered by that sequence. Optimistically update `scene_order` values in `setLocalScenes`, then call `reorderScenesInSequence(sequenceId, { scene_ids: reorderedSceneIds })`. On failure, revert to `previousScenes`.
   - Default (existing behavior): Cross-sequence scene drag — keep the existing `assignSceneToSequence` logic as-is.
5. Pass a new `onReorderScenes` callback prop to each `SortableSequenceSection` that triggers the within-sequence reorder logic. OR, since we're using a single DndContext, the handleDragEnd in SequencedSceneList will handle it centrally based on the `type` field.

**SortableSequenceSection.tsx changes:**

1. Import `SortableContext`, `verticalListSortingStrategy` from `@dnd-kit/sortable`.
2. Make the section header itself sortable for sequence reorder: Add `useSortable({ id: sequence.id, data: { type: "sequence" } })` hook at the component level. Apply `setNodeRef`, `transform`, `transition`, `attributes`, `listeners` to the sequence header wrapper div. Add a drag handle grip icon to the left of SequenceHeader.
3. Wrap the scene list inside `<SortableContext items={sortedScenes.map(s => s.scene_id)} strategy={verticalListSortingStrategy}>` to enable within-sequence reorder.
4. Update `DraggableSceneRow`'s `useSortable` call to include `data: { type: "scene-within-sequence", sequenceId: sequence.id }` so the parent DndContext can distinguish scene reorder from cross-sequence drag.
5. Keep the existing `useDroppable` for the scene container so cross-sequence drops still work (scenes dragged FROM another sequence land on this droppable zone).

**DnD Architecture (critical):** Use a single DndContext in SequencedSceneList.tsx. Route in handleDragEnd based on `active.data.current.type`. This avoids nested DndContext conflicts per Research Pitfall 1.

**Determining drag type in handleDragEnd:**
- `active.data.current.type === "sequence"` and `over` is also a sequence ID -> sequence reorder
- `active.data.current.type === "scene-within-sequence"` and `over.data.current?.type === "scene-within-sequence"` and both share same `sequenceId` -> within-sequence scene reorder
- Otherwise (scene dragged to different sequence droppable zone) -> existing cross-sequence assignment logic
