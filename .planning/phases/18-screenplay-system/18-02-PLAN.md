**Create `backend/vidpipe/api/screenplay.py`** following the `sequences.py` domain-split route pattern:

```python
screenplay_router = APIRouter(prefix="/api")
```

**Request/Response schemas** (define inline in the route file like sequences.py does):

- `ScreenplayResponse(BaseModel)` — All fields from the Screenplay model serialized: id (str), production_id (str), title, genre, status, logline, treatment, character_breakdowns, scene_breakdown, script, shot_list, text_model, generating_step, created_at (str), updated_at (str).
- `ScreenplayUpdate(BaseModel)` — Optional fields: title, genre, logline, treatment, character_breakdowns, scene_breakdown, script, shot_list, text_model. All Optional.
- `StatusUpdate(BaseModel)` — status: str (must be one of DRAFT, IN_REVIEW, LOCKED).
- `GenerateRequest(BaseModel)` — Optional text_model override: text_model: Optional[str] = None.

**CRUD + Status Endpoints (4):**

1. **`GET /productions/{production_id}/screenplay`** — Get or create. Query the screenplays table for production_id. If not found, create a new Screenplay with status=DRAFT and commit. Return ScreenplayResponse. This upsert pattern ensures the endpoint always returns a screenplay.

2. **`PUT /productions/{production_id}/screenplay`** — Update fields. Accept ScreenplayUpdate body. Query existing screenplay (404 if not found). If `screenplay.status == "LOCKED"`, return 409 Conflict with message "Screenplay is locked — unlock before editing". Apply all non-None fields from the update body using `model_fields_set` check (same pattern as sequences.py SequenceUpdate). Commit and return ScreenplayResponse.

3. **`PATCH /productions/{production_id}/screenplay/status`** — Accept StatusUpdate body. Validate status is one of DRAFT, IN_REVIEW, LOCKED. Update screenplay.status. Commit. Return ScreenplayResponse.

4. **`POST /productions/{production_id}/screenplay/generate-scenes`** — Create Scenes from LOCKED screenplay. Validate screenplay exists (404) and status == "LOCKED" (409 if not LOCKED — screenplay must be finalized before scene generation). Validate scene_breakdown is not empty (400). Check for existing scenes with `screenplay_breakdown_index IS NOT NULL` under this production — if found, return 409 "Scenes already generated from this screenplay. Delete existing scenes first or use force=true query param." If `force=true` query param, delete existing screenplay-linked scenes first.

    For each entry in `screenplay.scene_breakdown`:
    - Create a new `Scene` row with:
      - `production_id` = production_id
      - `prompt` = entry["intent"] (the narrative intent becomes the scene prompt)
      - `title` = entry["slugline"]
      - `style` = "cinematic" (default)
      - `aspect_ratio` = "16:9" (default)
      - `target_clip_duration` = 8 (default)
      - `status` = "draft"
      - `screenplay_breakdown_index` = entry["scene_number"] (the index into the breakdown array)
      - `screenplay_context` = entry dict as JSON (denormalized for storyboard enrichment)
      - `scene_order` = loop index (for sequence ordering)
    - Commit all scenes.
    - Return list of created scene summaries: `[{"scene_id": str, "title": str, "scene_number": int}]`.

**Error handling:** Wrap ScreenwriterService calls in try/except ValueError (for LOCKED status) → return 409. Let other exceptions propagate to the generic handler.

**Generation Endpoints (7):**

1. **`POST /productions/{production_id}/screenplay/generate`** — Full chain as BackgroundTask (202 response). The route handler extracts plain values (production_id, screenplay_id, text_model string, bible_context string, user_settings dict) from the current session BEFORE launching the background task. The background function accepts ONLY these plain values — NOT ORM objects or session references. Inside the background function: open `async with async_session() as session:`, load the Screenplay fresh by ID, construct adapter via `get_adapter(text_model or settings.models.storyboard_llm, user_settings)`, create ScreenwriterService(adapter), and call `screenwriter.generate_full(session, screenplay, bible_context, production_id=production_id)`. This pattern is critical because FastAPI BackgroundTasks run after the request session closes — reusing the request's session or ORM objects would cause DetachedInstanceError.

2. **`POST /productions/{production_id}/screenplay/generate-logline`** — Individual step. Same adapter construction pattern but calls only `generate_logline()`. Returns 200 with updated ScreenplayResponse (not background — individual steps are fast enough to run inline, ~5-10 seconds).

3. **`POST /productions/{production_id}/screenplay/generate-treatment`** — Calls `generate_treatment()`. Returns 200.

4. **`POST /productions/{production_id}/screenplay/generate-character-breakdowns`** — Calls `generate_character_breakdowns()`. Returns 200.

5. **`POST /productions/{production_id}/screenplay/generate-scene-breakdown`** — Calls `generate_scene_breakdown(session, screenplay, bible_context, production_id=production_id)`. Note: passes production_id for entity validation per SCRN-06. Returns 200.

6. **`POST /productions/{production_id}/screenplay/generate-shot-list`** — Calls `generate_shot_list()`. Returns 200.

7. **`POST /productions/{production_id}/screenplay/generate-script`** — Calls `generate_script()`. Returns 200.

**Shared pattern for inline generation endpoints (2-7):** Get or create screenplay. Load bible_context via `load_bible_context(session, production_id)`. Construct adapter via `get_adapter(request.text_model or screenplay.text_model or settings.models.storyboard_llm, user_settings)`. Create ScreenwriterService(adapter). Call the specific method. In `backend/vidpipe/pipeline/storyboard.py`, add screenplay context enrichment to the storyboard generation function. The enrichment must be additive — it ONLY activates when a Shot's parent Scene has `screenplay_context` set (not None). When no screenplay context exists, the existing storyboard generation path is completely unchanged (SCRN-14 — free-form fallback).

**Find the spot** in `generate_storyboard()` (or the main storyboard generation function) where the system prompt or full prompt is assembled, AFTER manifest/bible context is determined. Add a block like:

```python
# Phase 18: Screenplay context enrichment
screenplay_enrichment = ""
if hasattr(scene, 'screenplay_context') and scene.screenplay_context:
    breakdown = scene.screenplay_context
    parts = []
    parts.append(f"SCREENPLAY DIRECTION:")
    if breakdown.get("slugline"):
        parts.append(f"  Scene: {breakdown['slugline']}")
    if breakdown.get("intent"):
        parts.append(f"  Intent: {breakdown['intent']}")
    if breakdown.get("emotional_beat"):
        parts.append(f"  Emotional beat: {breakdown['emotional_beat']}")
    if breakdown.get("story_state_in"):
        parts.append(f"  Story state (entering): {breakdown['story_state_in']}")
    if breakdown.get("story_state_out"):
        parts.append(f"  Story state (leaving): {breakdown['story_state_out']}")
    if breakdown.get("characters_present"):
        chars = ", ".join(breakdown["characters_present"])
        parts.append(f"  Characters in scene: {chars}")
    if breakdown.get("set_ref"):
        parts.append(f"  Location/Set: {breakdown['set_ref']}")
    if breakdown.get("props_required"):
        props = ", ".join(breakdown["props_required"])
        parts.append(f"  Props: {props}")
    screenplay_enrichment = "\n".join(parts) + "\n\n"
```

Then inject `screenplay_enrichment` into the system prompt before the main prompt content. This provides structured narrative direction to the storyboard LLM without replacing its creative latitude.

**Key constraints:**
- The `scene` variable in `generate_storyboard` is a `Scene` ORM object — access `scene.screenplay_context` directly (it's the JSON column we added in Plan 01).
- Use `hasattr` guard for backward compatibility with Scene instances loaded before the column migration ran.
- Do NOT modify the function signature — the enrichment is data-driven from the Scene model.
- Do NOT change any existing prompt construction — only ADD the screenplay block when present.
- This satisfies SCRN-13 (Shot prompts include Character, Set, Prop prompt_tags from linked breakdown) and SCRN-14 (free-form storyboard remains as fallback).
