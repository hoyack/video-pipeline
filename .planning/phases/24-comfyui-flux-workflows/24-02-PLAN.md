Implementation:
- Import `build_flux_txt2img_workflow` and `find_comfyui_image_output` from comfyui_client
- Call builder with all parameters
- Queue workflow via `comfy_client.queue_prompt(workflow)`
- Poll loop: same pattern as `_generate_image_comfyui` (max_polls=120, poll_interval=3, check for "success"/"error"/"failed"/"cancelled")

3. **Add binding-based reference categorization** in the main `generate_keyframes()` function. When `is_comfyui` is True AND the model starts with "flux-", modify the image generation call site (around lines 750-870) to:

a. Check if scene has `production_bible_id` -- if so, attempt to import `resolve_tags_with_assets` from `vidpipe.services.tag_resolver` and resolve the current shot's prompt text
b. Categorize `ResolvedAssetRef[]` by `asset_type`:
   - CHARACTER with `lora_url` -> set `lora_filename` (the first CHARACTER with a lora_url)
   - CHARACTER without `lora_url` -> add `reference_image_urls[0]` to reference list
   - PROP -> add `reference_image_urls[0]` to reference list
   - SET -> add `reference_image_urls[0]` to reference list
c. Upload reference images to ComfyUI via `comfy_client.upload_image()` in parallel using `asyncio.gather()`, collecting the server-side filenames
d. Map aspect ratio to Flux dimensions via `_FLUX_RESOLUTIONS` from comfyui_client
e. Call `_generate_image_comfyui_flux()` with lora_filename, reference_image_filenames, and mapped width/height

If NO bindings are found or tag resolution fails, fall back to calling `_generate_image_comfyui_flux()` with just prompt, seed, and dimensions (no LoRA, no refs). This ensures Flux works even without a production bible.

For the is_comfyui routing block (around line 754), add an `elif image_model.startswith("flux-"):` branch BEFORE the existing Qwen branch. The existing Qwen path should remain as-is under an `else:` within the ComfyUI block.
