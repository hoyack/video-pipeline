**flux-txt2img-base.json** (FLUX-01):
Standard Flux.1 Dev text-to-image. Nodes:
- Node 10: VAELoader (ae.safetensors)
- Node 11: DualCLIPLoader (t5xxl_fp16.safetensors + clip_l.safetensors, type: "flux")
- Node 12: UNETLoader (flux1-dev.safetensors, weight_dtype: "default")
- Node 6: CLIPTextEncode (positive prompt, connected to node 11 output 0)
- Node 7: CLIPTextEncode (negative prompt, connected to node 11 output 0)
- Node 5: EmptySD3LatentImage (width: 1024, height: 1024, batch_size: 1)
- Node 13: ModelSamplingFlux (shift: 1.15, model from node 12 output 0)
- Node 3: KSampler (seed: 0, steps: 20, cfg: 1.0, sampler_name: "euler", scheduler: "simple", denoise: 1.0, model from node 13, positive from node 6, negative from node 7, latent from node 5)
- Node 8: VAEDecode (samples from node 3, vae from node 10)
- Node 9: SaveImage (filename_prefix: "flux-output", images from node 8)

**flux-txt2img-with-lora.json** (FLUX-02):
Same as base PLUS:
- Node 14: LoraLoaderModelOnly (lora_name: "placeholder.safetensors", strength_model: 0.8, model from node 12 output 0)
- Node 13 (ModelSamplingFlux) now takes model from node 14 output 0 (instead of 12)

**flux-txt2img-with-refs.json** (FLUX-03):
Same as base PLUS up to 3 reference image inputs via LoadImage nodes:
- Node 20: LoadImage (image: "ref_0.png") -- first reference
- Node 21: LoadImage (image: "ref_1.png") -- second reference (optional)
- Node 22: LoadImage (image: "ref_2.png") -- third reference (optional)
- Node 30: ImageBatch -- combines loaded images into a batch
- Node 31: CLIPVisionLoader (clip_name: "clip_vision_g.safetensors") -- for IP-Adapter/Redux style conditioning
- Node 32: CLIPVisionEncode (image from node 30, clip_vision from node 31) -- encodes references
- Node 33: unCLIPConditioning (conditioning from node 6 positive, clip_vision_output from node 32, strength: 0.65, noise_augmentation: 0.0)
- KSampler (node 3) positive input now connects to node 33 output 0 (instead of node 6)

Note: The reference injection uses unCLIPConditioning (built-in ComfyUI node, no custom extensions needed) rather than UNO custom nodes. This is more broadly compatible with ComfyUI servers. The PRD prefers UNO but the template can be swapped later when UNO availability is confirmed.

**flux-txt2img-full.json** (FLUX-04):
Combines LoRA (node 14) AND reference injection (nodes 20-33). Node 13 takes model from node 14 (LoRA output). KSampler positive connects to node 33 (reference-conditioned).

Each template must have `_meta` titles on every node for ComfyUI GUI compatibility.
