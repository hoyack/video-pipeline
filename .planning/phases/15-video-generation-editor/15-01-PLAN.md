**routes.py — Endpoint 1: `POST /api/projects`** (VGED-01, VGED-03):
1. Accept `CreateProjectRequest` body
2. Create `Project` with `status="draft"`, mapping fields from request (same field mapping pattern as existing `POST /api/generate` — check how that maps `style`, `aspect_ratio`, `clip_duration`, model fields, `audio_enabled`, `quality_mode`, `candidate_count`, `vision_model`)
3. Create `scene_count` empty `Scene` rows with `scene_index=0..N-1`, all text fields set to `""`, `status="pending"`
4. If `manifest_id` provided, handle manifest snapshotting (reuse same manifest snapshot logic from existing `POST /api/generate`)
5. Return 201 with `{"project_id": str(project.id), "status": "draft", "scene_count": request.scene_count}`
6. Do NOT start the pipeline or add any background tasks

**routes.py — Endpoint 2: `POST /api/projects/{project_id}/generate`** (VGED-02):
1. Accept `StartGenerationRequest` body
2. Load project, verify status is in `("draft", "stopped", "staged", "failed", "complete")` — if not, return 409
3. Apply optional model/config overrides from request body to project columns
4. If `run_through` is provided and not "all", set `project.run_through` (existing column). If "all" or None, set `project.run_through = None`
5. Transition status: if currently "draft", set to "pending". If "stopped"/"staged"/"failed"/"complete", follow the existing resume pattern (look at how `POST /api/projects/{id}/resume` works and replicate)
6. Commit and launch `background_tasks.add_task(run_pipeline_background, project_id)`
7. Return 202 with `{"project_id": str(project_id), "status": "pending"}`

**routes.py — Endpoint 3: `PUT /api/projects/{project_id}/final-video`** (VGED-04):
1. Accept `UploadFile` (multipart)
2. Validate file content_type starts with "video/"
3. Save to `tmp/{project_id}/output/final.mp4` (matching existing pipeline output path convention — check `stitcher.py` for exact path pattern)
4. Set `project.output_path` to the saved file path
5. Commit and return 200 with updated project info
