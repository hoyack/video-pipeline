Modify all four pipeline stages (storyboard, keyframes, video_gen, stitcher) to support gap-filling mode where existing content is preserved and only missing assets are generated. Add per-scene stop flag checking and generation_status updates.

Purpose: The VideoGenEditor allows users to pre-populate scene text, keyframes, and clips before running the pipeline. The pipeline must detect what already exists and only fill gaps. Additionally, pause/resume must work at per-scene granularity (not just between stages) and the frontend needs per-scene generation_status for real-time spinners.

Output: Pipeline stages that skip existing content, set/clear generation_status before/after each operation, and check the stop flag inside per-scene loops.

**storyboard.py — Gap-filling mode** (VGED-06):

In the main `generate_storyboard` function, BEFORE the LLM call:
1. Load all existing Scene rows for the project (they already exist from `POST /api/projects` draft creation)
2. Partition scenes into two groups:
   - `filled_scenes`: scenes where `scene_description.strip()` is non-empty (user-provided text)
   - `empty_scenes`: scenes where `scene_description.strip()` is empty (need generation)
3. If `empty_scenes` is empty, log "All scenes have text, skipping storyboard" and transition `project.status = "keyframing"`, commit, and return early
4. When calling the LLM for storyboard generation:
   - Include filled scenes as fixed context in the prompt. Format: "Scene {idx} (provided by user): {scene_description}" for each filled scene
   - Request generation for empty scene indices only
   - Tell the LLM: "Generate content ONLY for the following scene indices: {list}. Maintain narrative continuity with the provided scenes."
5. After LLM response, only write text to empty scenes — do NOT overwrite user-provided text in filled scenes
6. Set `generation_status = "generating_text"` on each empty scene before generating, and `generation_status = None` after

**IMPORTANT for storyboard.py gap-filling:** The existing storyboard function creates Scene rows during generation. For draft projects, Scene rows already exist (created by POST /api/projects). The function must detect this: if scenes already exist for the project, update existing rows rather than creating new ones. Check the current code for how it creates scenes and add a branch: `if existing_scenes: update_existing() else: create_new()`.

**keyframes.py — Gap-filling mode** (VGED-06):

In the main `generate_keyframes` function, for each scene in the loop:
1. BEFORE generating start keyframe: query for existing Keyframe with `position="start"` for this scene. If it exists, skip start keyframe generation.
2. BEFORE generating end keyframe: query for existing Keyframe with `position="end"` for this scene. If it exists, skip end keyframe generation.
3. If both keyframes exist, skip the entire scene.
4. KEYF-03 continuity handling: When scene N has a user-uploaded start keyframe but scene N-1 has no end keyframe, the existing daisy-chain logic (`scene N start = scene N-1 end`) should still work — the uploaded start keyframe becomes the "previous end" for conditioning.

**keyframes.py — Per-scene generation_status** (VGED-05):
1. Before generating start keyframe: `scene.generation_status = "generating_start_kf"; await session.commit()`
2. Before generating end keyframe: `scene.generation_status = "generating_end_kf"; await session.commit()`
3. After completing both (or skipping): `scene.generation_status = None; await session.commit()`
4. On exception: `scene.generation_status = "failed"; await session.commit()` then re-raise
