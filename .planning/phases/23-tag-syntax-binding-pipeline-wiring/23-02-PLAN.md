**Part A: Add bound-assets/summary endpoint to bindings.py**

Add a new GET endpoint at the end of bindings.py (before the SoundBinding section or at the very end):

```python
@bindings_router.get("/production-bibles/{bible_id}/bound-assets/summary")
async def get_bound_assets_summary(bible_id: str):
    """Return flat list of all bindings with tags, names, types, and primary thumbnails.

    Combines CastBindings, SetBindings, and PropBindings into a single list
    for frontend consumption (autocomplete, tag reference sheets).
    No pagination -- typical bibles have 5-20 bindings.
    """
```

Implementation:
1. Validate bible exists via `_validate_bible(session, bible_id)`.
2. Query all CastBindings, SetBindings, PropBindings for this bible (3 queries).
3. Batch-load referenced entities for names:
   - Actors by id (for cast bindings)
   - LibrarySets by id (for set bindings)
   - LibraryProps by id (for prop bindings)
4. Batch-load primary refs for thumbnails:
   - ActorRef where is_primary=True for actor_ids
   - LibrarySetRef where is_primary=True for set_ids
   - LibraryPropRef where is_primary=True for prop_ids
5. Build flat response list where each item has:
   - `tag`: binding.tag (string)
   - `name`: character_name for cast, production_name or entity.name for set/prop
   - `type`: "CHARACTER" | "SET" | "PROP"
   - `primary_thumbnail_url`: from primary ref lookup, or null
   - `description`: actor.base_appearance_prompt for CHARACTER, lib_set.reverse_prompt for SET, lib_prop.appearance_prompt for PROP. Truncated to 200 chars. Null if entity deleted.
6. Sort: CHARACTER first, then SET, then PROP (within each type, by tag alphabetically).
7. Return the list directly (FastAPI auto-serializes to JSON array).
