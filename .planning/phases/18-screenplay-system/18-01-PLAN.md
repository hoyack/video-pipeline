class Screenplay(Base):
    """Screenplay entity attached 1:1 to a Production.

    Stores structured narrative content: logline, treatment, character breakdowns,
    scene breakdown, script, and shot list. Generated incrementally by ScreenwriterService.

    Spec reference: Phase 18 Screenplay System (SCRN-01, SCRN-02, SCRN-05)
    """
    __tablename__ = "screenplays"

    id: Mapped[uuid.UUID] = mapped_column(primary_key=True, default=uuid.uuid4)
    production_id: Mapped[uuid.UUID] = mapped_column(
        ForeignKey("productions.id"), unique=True, index=True
    )
    title: Mapped[Optional[str]] = mapped_column(String(200), nullable=True)
    genre: Mapped[Optional[str]] = mapped_column(String(100), nullable=True)
    status: Mapped[str] = mapped_column(String(20), default="DRAFT")  # DRAFT/IN_REVIEW/LOCKED
    logline: Mapped[Optional[str]] = mapped_column(Text, nullable=True)
    treatment: Mapped[Optional[str]] = mapped_column(Text, nullable=True)
    character_breakdowns: Mapped[Optional[dict]] = mapped_column(JSON, nullable=True)
    scene_breakdown: Mapped[Optional[list]] = mapped_column(JSON, nullable=True)
    script: Mapped[Optional[str]] = mapped_column(Text, nullable=True)
    shot_list: Mapped[Optional[list]] = mapped_column(JSON, nullable=True)
    text_model: Mapped[Optional[str]] = mapped_column(String(100), nullable=True)
    generating_step: Mapped[Optional[str]] = mapped_column(String(50), nullable=True)  # Current step being generated (for progress)

```python
"""Pydantic schemas for Screenplay LLM structured output and API responses."""
from typing import Optional
from pydantic import BaseModel

class LoglineOutput(BaseModel):
    """LLM output for logline generation."""
    logline: str
    genre: str  # e.g. "Action", "Drama", "Comedy", "Sci-Fi"

class TreatmentOutput(BaseModel):
    """LLM output for treatment generation."""
    treatment: str  # 2-5 paragraph narrative treatment

class CharacterBreakdownEntry(BaseModel):
    """Single character breakdown within the screenplay."""
    name: str
    role: str  # PROTAGONIST, ANTAGONIST, SUPPORTING, EXTRA
    arc: str
    description: str
    manifest_tag: Optional[str] = None  # e.g. CHAR_01 if from Production Bible

class CharacterBreakdownsOutput(BaseModel):
    """LLM output for character breakdowns."""
    characters: list[CharacterBreakdownEntry]

class SceneBreakdownEntry(BaseModel):
    """Single scene breakdown entry."""
    scene_number: int
    slugline: str  # e.g. "INT. OFFICE - DAY"
    intent: str  # narrative intent; becomes scene.prompt
    emotional_beat: str
    story_state_in: str
    story_state_out: str
    characters_present: list[str]  # manifest_tags or character names
    set_ref: Optional[str] = None  # set manifest_tag or name
    props_required: list[str] = []

class SceneBreakdownOutput(BaseModel):
    """LLM output for scene breakdown."""
    scene_count: int
    scenes: list[SceneBreakdownEntry]

class ShotListEntry(BaseModel):
    """Single shot within a scene's shot list."""
    scene_number: int
    shot_number: int
    shot_type: str  # e.g. "WIDE", "CLOSE-UP", "MEDIUM", "OTS", "POV"
    camera_movement: str  # e.g. "STATIC", "PAN LEFT", "DOLLY IN", "TRACKING"
    action_notes: str  # What happens in this shot
    duration_hint: str  # e.g. "3-5s", "2s"

class ShotListOutput(BaseModel):
    """LLM output for shot list generation."""
    shots: list[ShotListEntry]

class ScriptOutput(BaseModel):
    """LLM output for full script."""
    script: str  # Full screenplay script text
```

**Create `backend/vidpipe/services/screenwriter.py`** with the ScreenwriterService class:

The service follows the CVAnalysisService pattern (class-based with adapter injection). Each method:
1. Checks screenplay.status != "LOCKED" (raise ValueError if so)
2. Builds a prompt with Production Bible context (loaded via `load_manifest_assets` + `format_asset_registry` from `manifest_service.py`)
3. Sets `screenplay.generating_step = step_name` and commits (for progress polling)
4. Calls `self._adapter.generate_text(prompt, schema=OutputSchema, temperature=..., max_retries=3)`
5. Updates the relevant Screenplay field with the result
6. Clears `screenplay.generating_step = None`
7. Commits (incremental — user sees progress immediately)

**Methods:**
- `async def generate_logline(session, screenplay, bible_context="")` — Uses LoglineOutput schema. Sets `screenplay.logline` and `screenplay.genre`. Temperature 0.8.
- `async def generate_treatment(session, screenplay, bible_context="")` — Uses TreatmentOutput. Requires logline to exist. Includes logline in prompt context. Temperature 0.7.
- `async def generate_character_breakdowns(session, screenplay, bible_context="")` — Uses CharacterBreakdownsOutput. Requires logline + treatment. Stores result as list of dicts in `screenplay.character_breakdowns`. Temperature 0.7.
- `async def generate_scene_breakdown(session, screenplay, bible_context="", production_id=None)` — Uses SceneBreakdownOutput. Requires logline + treatment + character_breakdowns. Stores breakdown entries as list of dicts in `screenplay.scene_breakdown`. Temperature 0.7.

    **Post-LLM entity validation (SCRN-06):** After LLM returns the SceneBreakdownOutput, if `production_id` is provided, load Character, Set, and Prop entities for the production's bible from the database. For each SceneBreakdownEntry, validate `characters_present` tags against actual Character entity `prompt_tags`. Also validate `set_ref` against Set entity `prompt_tags` and `props_required` against Prop entity `prompt_tags`. For any tag that doesn't match an existing entity, log a warning: `logger.warning(f"Unresolved tag '{tag}' in scene {entry.scene_number} — no matching entity in Production Bible")`. Do NOT crash on unresolved tags — the LLM may invent characters not yet in the bible, and that's acceptable. The validation is informational, not blocking. Store resolved/unresolved status in each entry dict as `_resolved_characters`, `_resolved_set`, `_resolved_props` boolean flags for downstream consumers.

- `async def generate_shot_list(session, screenplay, bible_context="")` — Uses ShotListOutput schema (new Pydantic schema, see below). Requires scene_breakdown to exist. Generates coarse shot-level notes for each scene (shot type, camera, action notes). Stores result as list of dicts in `screenplay.shot_list`. Temperature 0.7. This is independently regeneratable per SCRN-09.
- `async def generate_script(session, screenplay, bible_context="")` — Uses ScriptOutput. Requires all prior steps. Stores result in `screenplay.script`. Temperature 0.7. For long productions, pass a SUMMARIZED form of prior steps (not full treatment verbatim) to avoid context window overflow.
- `async def generate_full(session, screenplay, bible_context="", production_id=None)` — Runs all 6 steps in sequence: logline → treatment → character_breakdowns → scene_breakdown → shot_list → script. Passes `production_id` to `generate_scene_breakdown` for entity validation.

**Prompt construction helpers** (module-level functions):
- `_build_logline_prompt(screenplay, bible_context)` — System prompt instructs LLM to create a compelling logline for the production. Includes production title + bible_context if available.
- `_build_treatment_prompt(screenplay, bible_context)` — Includes logline. Instructs 2-5 paragraph narrative treatment.
- `_build_character_breakdowns_prompt(screenplay, bible_context)` — Includes logline + treatment. If bible_context has Characters, instructs LLM to use their manifest_tags.
- `_build_scene_breakdown_prompt(screenplay, bible_context)` — Includes all prior. Instructs LLM to produce SceneBreakdownEntry list with sluglines, intents, emotional beats, and character/set/prop references using manifest_tags.
- `_build_shot_list_prompt(screenplay, bible_context)` — Includes scene breakdown entries. Instructs LLM to produce per-scene shot-level notes with shot type, camera movement, action notes, and duration hints.
- `_build_script_prompt(screenplay, bible_context)` — Includes summarized logline, character list, and scene breakdown entries. Instructs full screenplay script.

**Bible context loading** (helper):
- `async def load_bible_context(session, production_id)` — Loads the Production Bible associated with the production (via Scene.production_bible_id or direct query) and returns formatted asset registry string. Uses `load_manifest_assets()` + `format_asset_registry()` from `manifest_service.py`. Returns empty string if no Production Bible exists. This is a convenience wrapper for the API layer.

**Constructor:**
```python
class ScreenwriterService:
    def __init__(self, adapter: LLMAdapter):
        self._adapter = adapter
```

The adapter is constructed by the caller (API route) via `get_adapter(screenplay.text_model or settings.models.storyboard_llm, user_settings)`.

Do NOT import event_bus — progress is tracked via the `generating_step` column on Screenplay, which the frontend polls via GET endpoint. This is simpler than event_bus and consistent with how `generation_status` works on Shot.
