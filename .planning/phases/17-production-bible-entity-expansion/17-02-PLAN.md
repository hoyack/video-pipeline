  <name>Task 1: Create Character, Wardrobe, VoiceProfile CRUD routes</name>
  <files>backend/vidpipe/api/characters.py, backend/vidpipe/api/app.py</files>
  <action>
Create `backend/vidpipe/api/characters.py` following the `sequences.py` pattern exactly (APIRouter with prefix="/api", Pydantic schemas inline, async_session() for DB access).

**Router:** `character_router = APIRouter(prefix="/api")`

**Pydantic request schemas** (all fields Optional except where noted):
- `CharacterCreate`: name (str, required), role (str, required — validate against {"PROTAGONIST", "ANTAGONIST", "SUPPORTING", "EXTRA"}), description, arc, base_appearance, prompt_tags (list[str])
- `CharacterUpdate`: name, role (validate if provided), description, arc, base_appearance, prompt_tags
- `WardrobeCreate`: label (str, required), scene_context, prompt_descriptor, is_default (bool, default False)
- `WardrobeUpdate`: label, scene_context, prompt_descriptor, is_default
- `VoiceProfileUpsert`: voice_id, adapter_type (default "ELEVENLABS"), style_notes, sample_audio

**Character endpoints:**
1. `GET /production-bibles/{production_bible_id}/characters` — list all characters for a bible. Return list of character dicts with nested wardrobe list and voice_profile (or null). Query with selectinload or separate queries.
2. `POST /production-bibles/{production_bible_id}/characters` (201) — create character. Validate production_bible_id exists (404 if not). Validate role against VALID_ROLES set (422 if invalid).
3. `GET /characters/{character_id}` — get single character with wardrobe list and voice_profile.
4. `PUT /characters/{character_id}` — update character fields. Use `model_fields_set` pattern from sequences.py for optional field clearing.
5. `DELETE /characters/{character_id}` — delete character. CASCADE delete wardrobes and voice_profile via separate queries (SQLAlchemy doesn't auto-cascade without relationship config). Return 204.
6. `GET /characters/{character_id}/prompt-context` — compute and return injection string on demand. Format: `"CHARACTER [{name}]: {role}. {description}. Base appearance: {base_appearance}. Wardrobe (default): '{wardrobe.label}' - {wardrobe.prompt_descriptor}. Prompt tags: {prompt_tags}"`. Return `{"entity_id": str, "injection_string": str}`.

**Wardrobe endpoints:**
7. `GET /characters/{character_id}/wardrobes` — list wardrobes for character.
8. `POST /characters/{character_id}/wardrobes` (201) — create wardrobe item.
9. `PUT /wardrobes/{wardrobe_id}` — update wardrobe item.
10. `DELETE /wardrobes/{wardrobe_id}` — delete wardrobe item (204).

**VoiceProfile endpoints:**
11. `GET /characters/{character_id}/voice-profile` — get voice profile (404 if none).
12. `PUT /characters/{character_id}/voice-profile` — upsert voice profile. If exists, update; if not, create. Return the profile.
13. `DELETE /characters/{character_id}/voice-profile` — delete voice profile (204).

**Response helper:** Create a `_character_to_dict(char, wardrobes, voice_profile)` helper that builds the response dict with nested sub-entities.

**Register in app.py:** Add `from vidpipe.api.characters import character_router` and `app.include_router(character_router)` after the sequence_router line.

Do NOT use relationship() on ORM models — keep queries explicit in route handlers (consistent with sequences.py pattern).

**Deferred:** `POST /characters/{character_id}/upload-actor-ref` endpoint for uploading actor reference images is NOT included in this plan. The `actor_refs` JSON column stores image keys but the upload mechanism is deferred to a future phase. Characters created via migration will populate actor_refs from existing Asset reference_image_url; characters created via UI will have actor_refs=null until the upload endpoint exists.

  <name>Task 2: Create Set, SonicIdentity, Prop CRUD routes with LLM Vision</name>
  <files>backend/vidpipe/api/sets_props.py, backend/vidpipe/api/app.py</files>
  <action>
Create `backend/vidpipe/api/sets_props.py` following the same pattern.

**Router:** `sets_props_router = APIRouter(prefix="/api")`

**Pydantic request schemas:**
- `SetCreate`: name (str, required), style_tags (list[str]), lighting_notes, prompt_tags (list[str])
- `SetUpdate`: name, reverse_prompt, style_tags, lighting_notes, prompt_tags
- `SonicIdentityUpsert`: ambience_description, reference_audio, generation_prompt
- `PropCreate`: name (str, required), description, associated_characters (list[str]), prompt_tags (list[str])
- `PropUpdate`: name, description, associated_characters, prompt_tags

**Set endpoints:**
1. `GET /production-bibles/{production_bible_id}/sets` — list all sets for a bible, each with nested sonic_identity (or null).
2. `POST /production-bibles/{production_bible_id}/sets` (201) — create set. Validate bible exists.
3. `GET /sets/{set_id}` — get single set with sonic_identity.
4. `PUT /sets/{set_id}` — update set. Use `model_fields_set` for optional clearing.
5. `DELETE /sets/{set_id}` — delete set + its sonic_identity. Return 204.
6. `POST /sets/{set_id}/upload-reference` — accept UploadFile, save image using the pattern from routes.py `upload_asset_image`. Save to `tmp/manifests/{production_bible_id}/sets/{set_id}/{filename}`. Update `set.reference_image` with the path/key. Then run inline LLM Vision reverse-prompt:
   ```python
   try:
       from vidpipe.services.reverse_prompt_service import ReversePromptService
       svc = ReversePromptService()
       result = await svc.reverse_prompt_asset(local_path, "ENVIRONMENT", user_name=set_row.name)
       set_row.reverse_prompt = result["reverse_prompt"]
   except Exception as e:
       logger.warning("Set reverse-prompt failed for %s: %s", set_id, e)
       # Continue — reverse_prompt stays None (graceful degradation)
   ```
   Commit and return updated set. This satisfies PBEX-09.
7. `GET /sets/{set_id}/prompt-context` — compute injection string: `"SET [{name}]: {reverse_prompt}. Lighting: {lighting_notes}. Style: {style_tags}. Prompt tags: {prompt_tags}"`. Return `{"entity_id": str, "injection_string": str}`.

**SonicIdentity endpoints:**
8. `GET /sets/{set_id}/sonic-identity` — get sonic identity (404 if none).
9. `PUT /sets/{set_id}/sonic-identity` — upsert sonic identity.
10. `DELETE /sets/{set_id}/sonic-identity` — delete (204).

**Prop endpoints:**
11. `GET /production-bibles/{production_bible_id}/props` — list all props for a bible.
12. `POST /production-bibles/{production_bible_id}/props` (201) — create prop. Validate bible exists.
13. `GET /props/{prop_id}` — get single prop.
14. `PUT /props/{prop_id}` — update prop.
15. `DELETE /props/{prop_id}` — delete prop (204).
16. `POST /props/{prop_id}/upload-reference` — accept UploadFile, save image, update prop.reference_image. No LLM Vision call for props (they don't have reverse_prompt).

**Register in app.py:** Add `from vidpipe.api.sets_props import sets_props_router` and `app.include_router(sets_props_router)`.

For file uploads, use `from fastapi import File, UploadFile` and follow the existing `upload_asset_image` pattern in routes.py for saving files (handling both local and S3 storage backends).
